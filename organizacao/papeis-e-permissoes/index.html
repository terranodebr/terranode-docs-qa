Papéis e permissões¶

Cada pessoa tem um papel na organização, e esse papel define o que ela vê e pode fazer. A ideia é que quem configura catálogos e formulários tenha ferramentas diferentes de quem coleta, e que quem coleta encontre uma interface simples, sem telas que não vai usar. Dentro de cada projeto existe ainda um papel de projeto, que diz quem conduz aquele trabalho específico.

Cada membro tem um papel na organização, e o papel decide o que a pessoa pode fazer nela. As regras são as mesmas no web app, no app de campo, na linha de comando tn e na API. Esta página é a casa de todas elas.

Os três papéis¶

Papel Para quem é Como aparece no CLI e na API
Gestor Quem administra a organização: convida pessoas, cuida de chaves de API, dispositivos e integrações, e faz tudo o que um Editor faz. owner
Editor Quem monta o trabalho: catálogos, formulários e projetos. editor
Coletor Quem coleta dados em campo com o app. field

O web app mostra os nomes em português. A linha de comando e a API usam owner, editor e field. Uma pessoa pode ter papéis diferentes em organizações diferentes.

Quem muda o papel de alguém é um Gestor, pela página Membros; veja Membros e convites.

Um Coletor que é gestor de um projeto vê as posições, os trajetos e a atividade de todos os coletores daquele projeto, e não só os próprios.

Quando você abre no web app uma seção que o seu papel não permite, a página mostra Acesso restrito e diz para quais papéis ela está disponível. O menu lateral já esconde o que você não pode usar: um Coletor, por exemplo, não vê Catálogos nem Integrações.

Para quem usa a API ou o CLI

Internamente cada linha da tabela corresponde a uma ou mais permissões com nomes no formato recurso:ação, como catalog:read, survey:write ou member:manage. São esses nomes que aparecem em tn auth whoami e na resposta de /auth/me.

Papéis dentro de um projeto¶

Além do papel na organização, cada pessoa pode ter um papel em cada projeto de que participa: Gestor, Coletor ou Revisor. Eles são definidos na aba de equipe do projeto; veja Equipe do projeto. O Gestor de um projeto não é o mesmo que o Gestor da organização: esta documentação escreve "gestor do projeto" quando se refere ao papel dentro do projeto.

Para as permissões, o que importa é ser gestor do projeto. Quem cria o projeto é gestor dele desde o início e não pode ser retirado desse papel. Coletor e revisor de projeto não acrescentam nada ao que o papel da organização já permite.

Editar um projeto exige duas coisas¶

  1. Um papel que permita editar projetos. Os três papéis permitem.
  2. Fazer parte daquele projeto como criador ou gestor do projeto.

Ser Gestor ou Editor não basta. O projeto criado por outra pessoa continua sendo dela para editar, a menos que você seja incluído como gestor do projeto. A única exceção é um projeto sem criador registrado (por exemplo, porque a conta de quem criou foi excluída): qualquer Gestor pode editá-lo.

Um Coletor que é gestor de um projeto pode editá-lo, mas continua sem poder criar ou arquivar projetos: gerenciar um projeto não muda o papel na organização.

Chaves de API também têm papel¶

Quando um Gestor cria uma chave de API, escolhe um papel para ela, e a chave faz exatamente o que aquele papel faz, nada além. Uma chave com papel de Editor, por exemplo, mexe em catálogos e formulários, mas não cria integrações nem convida pessoas. Um projeto criado por uma chave tem a chave como gestor do projeto. Como criar e revogar chaves está em Chaves de API e dispositivos.

Um dispositivo registrado pelo app de campo não tem papel próprio: ele usa o papel da pessoa que entrou nele.

O que só a organização terranode pode fazer¶

A organização da própria terranode é a única que pode publicar catálogos públicos, visíveis em modo somente leitura para todas as outras organizações, e manter os catálogos de Dados públicos. Nenhum papel em outra organização libera isso, nem Gestor. O que você pode fazer com esses catálogos está em Catálogos públicos e dados públicos.

Como ver suas permissões¶

  • No web app, o seu papel aparece ao lado do seu nome no canto superior.
  • Na linha de comando, tn auth whoami mostra quem você é, as organizações de que faz parte e, para cada uma, a lista de permissões. É a mesma lista que o web app usa para decidir o que mostrar.

Uma mudança de papel vale na hora, sem precisar entrar de novo.
