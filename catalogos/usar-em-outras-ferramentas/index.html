Usar os dados em outras ferramentas¶

Os dados de um catálogo muitas vezes precisam sair do terranode, seja para uma análise no QGIS, para um relatório ou para outro sistema. Em vez de exportar arquivos, você pode ler as fontes de dados diretamente, por um padrão aberto. Esta página mostra como fazer isso e explica também alguns comportamentos dos mapas do próprio web app.

Os dados de um catálogo não ficam presos ao terranode. Toda fonte de dados vetorial pode ser lida por QGIS, ArcGIS Pro, FME, GDAL e qualquer cliente que fale OGC API Features, um padrão aberto de leitura de feições.

Qualquer pessoa com um token válido da organização (o token de login do tn ou uma chave de API) consegue ler os dados pela OGC API. Como obter e guardar tokens está em Chaves de API e dispositivos e em API e SDK.

OGC API Features¶

Cada catálogo da sua organização, e cada catálogo público da terranode, tem o próprio servidor OGC, somente leitura:

https://<api>/api/v1/ogc/<organização>/catalogs/<catálogo>

Troque <api> pelo endereço da API da sua instalação (o mesmo que você configura no tn), <organização> pelo slug ou id da organização e <catálogo> pelo slug ou id do catálogo.

Caminho O que devolve
/ Página inicial com links
/conformance As partes do padrão implementadas
/collections Uma coleção por fonte de dados vetorial
/collections/<fonte>/items As feições da fonte, em GeoJSON
/collections/<fonte>/items/<id> Uma feição

A documentação interativa fica em https://<api>/api/v1/ogc/docs e o esquema em https://<api>/api/v1/ogc/openapi.json; os dois também pedem token.

Regras:

  • São servidos os catálogos da sua organização e os catálogos públicos da terranode, inclusive os de dados públicos. Use sempre o slug da sua organização no endereço, mesmo para um catálogo público.
  • Se um catálogo seu tiver o mesmo slug de um catálogo público, o slug é recusado como ambíguo; use o id do catálogo.
  • Só fontes vetoriais com geometria viram coleções. Rasters e fontes Sem geometria ficam de fora.
  • O id de cada coleção é o slug da fonte de dados; o id de cada feição é o número da linha na tabela.
  • As geometrias saem em WGS84 (EPSG:4326), no formato GeoJSON.
  • Um catálogo inexistente ou de outra organização responde "Not found", sem revelar se existe.

Autenticação¶

Envie o token no cabeçalho Authorization:

curl -H "Authorization: Bearer <token>" \
  "https://<api>/api/v1/ogc/minha-org/catalogs/meu-catalogo/collections"

A organização vem da URL, então não é preciso nenhum outro cabeçalho. Para scripts e integrações use uma chave de API; para uso pessoal o token do tn auth login também serve, mas expira em 30 dias.

Paginação e filtros¶

Parâmetro Uso Limites
limit Feições por página Padrão 10, máximo 100
offset Pular as primeiras N feições Não combina com after
after Cursor da página seguinte, copiado do link next da resposta Mais rápido que offset em tabelas grandes
bbox Recorte por retângulo: oeste,sul,leste,norte em graus Quatro números, oeste ≤ leste e sul ≤ norte
<campo>=<valor> Igualdade em um campo da tabela O campo precisa existir; o valor precisa ter o tipo da coluna

Exemplo: as feições de lotes cujo campo situacao é ativo, dentro de um retângulo, 100 por página:

/collections/lotes/items?situacao=ativo&bbox=-47.1,-23.0,-46.9,-22.8&limit=100

Não existem filtros por data, expressões (CQL), outros sistemas de coordenadas nem escrita: a API é só de leitura.

No QGIS¶

  1. Escolha adicionar uma camada WFS / OGC API - Features e crie uma nova conexão.
  2. Em URL, informe o endereço do catálogo (o caminho que termina em /catalogs/<catálogo>).
  3. Na autenticação, crie uma configuração que envie o cabeçalho Authorization com o valor Bearer <token>.
  4. Conecte: cada fonte de dados aparece como uma camada. Ao adicionar, o QGIS pede as feições em páginas e aplica o recorte da tela.

Com o GDAL (3.6 ou mais recente), o mesmo catálogo pode ser copiado para um GeoPackage:

ogr2ogr -f GPKG catalogo.gpkg \
  "OAPIF:https://<api>/api/v1/ogc/minha-org/catalogs/meu-catalogo" \
  --config GDAL_HTTP_HEADERS "Authorization: Bearer <token>"

Os mapas do web app¶

Nos mapas do terranode as fontes vetoriais são desenhadas a partir de tiles, pedaços do mapa gerados por zoom. Isso explica alguns comportamentos:

  • "Aproxime até o zoom N para ver esta camada · atual M": uma camada densa só é desenhada a partir de um zoom mínimo, calculado para que o tile mais cheio tenha no máximo 25 000 feições; esse mínimo nunca passa do zoom 10. Aproxime o mapa até o zoom indicado. O aviso vale para o mapa, não para a tabela de atributos nem para a OGC API, que sempre devolvem tudo.
  • Em zooms afastados, linhas e polígonos são simplificados a 1 pixel e formas menores que um pixel não são desenhadas. Pontos nunca são descartados.
  • Depois de um envio ou de uma cópia, o mapa pode levar alguns minutos a mais que a fonte para ficar pronto; rasters mostram Gerando até lá.
  • O acesso aos tiles é por pessoa e expira sozinho. Quem perde o acesso ao catálogo pode continuar vendo o mapa já carregado por até 24 horas; os dados em si não são mais servidos.

Não há um endereço público de tiles para usar em outros visualizadores: para consumir os dados fora do terranode, use a OGC API Features acima ou a saída --json do tn (veja Linha de comando tn).
