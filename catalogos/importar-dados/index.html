Importar dados¶

Em geral os dados que a equipe precisa já existem em algum formato: shapefiles, GeoPackages, planilhas, imagens de satélite. O envio de arquivos é a forma de trazer esses dados para um catálogo. Você manda o arquivo como está, e o terranode abre, converte e prepara cada camada para aparecer no mapa e no aplicativo.

Você traz dados para um catálogo enviando arquivos. Cada arquivo enviado é um envio; o terranode lê o que há dentro dele e cria uma fonte de dados para cada camada vetorial ou raster que encontrar. Para o que é um catálogo e uma fonte de dados, veja Catálogos e fontes de dados.

Gestores e Editores podem enviar arquivos; Coletores não têm acesso aos catálogos. Envios só são aceitos em catálogos de origem Gerenciado: catálogos de Integração e de Dados públicos são atualizados sozinhos e recusam envios manuais.

Formatos aceitos¶

Tipo Formato Como enviar
Vetor Shapefile (.shp, .dbf, .shx e companheiros) Dentro de um .zip
Vetor MapInfo (.tab, .mif) e File Geodatabase (pasta .gdb) Dentro de um .zip
Vetor GeoPackage (.gpkg), GeoJSON (.geojson, .json), FlatGeobuf (.fgb) Arquivo solto ou em .zip
Vetor CSV (.csv) com colunas de coordenadas Arquivo solto ou em .zip
Raster GeoTIFF (.tif, .tiff), ERDAS Imagine (.img) Arquivo solto ou em .zip

Um .zip pode conter vários conjuntos de dados ao mesmo tempo, inclusive em subpastas; cada um vira um item do envio. Arquivos com outra extensão são recusados na hora com Tipo de arquivo não suportado.

O que os dados precisam ter¶

  • Sistema de referência (CRS) definido, vetor ou raster. Um CRS de engenharia ou local, sem referência à Terra, faz o item falhar.
  • CSV: uma coluna chamada longitude, lon, long ou x e outra chamada latitude, lat ou y. As coordenadas são lidas como WGS84. Um CSV sem essas colunas não tem geometria e o item é ignorado.
  • Shapefile sem codificação declarada: o texto é lido como UTF-8 e, se não for válido, como ISO-8859-1.

Limites¶

Limite Valor
Tamanho por arquivo Até 2 GB, como indica o diálogo de envio
Itens por envio (camadas e rasters contados em todos os arquivos selecionados) 128
Tempo de conversão por camada vetorial 10 minutos

O diálogo conta os itens antes de enviar (entradas do zip, tabelas do GeoPackage) e recusa a seleção se passar do limite. Para enviar mais, divida em vários envios.

Enviar pelo web app¶

  1. Abra o catálogo e escolha Enviar dados.
  2. No diálogo Enviar dados para o catálogo, arraste os arquivos ou escolha selecione do computador. O diálogo mostra quantos arquivos e quantos itens a seleção vai gerar.
  3. Confirme. A etapa Processamento acompanha cada item com os estados Na fila, Processando, Concluído ou Falhou.
  4. Você pode fechar o diálogo: o processamento continua no servidor, e a aba Fontes de dados mostra o cartão Processando com os mesmos itens.

Quando um item termina com sucesso, a fonte de dados aparece na tabela e o item some do cartão em instantes. Itens que falharam ou foram ignorados ficam no cartão até você recarregar a página, para que você veja o motivo.

O que acontece com o arquivo¶

  • O terranode abre o arquivo e descobre o que há dentro: uma camada vetorial ou um raster vira um item; um GeoPackage com três tabelas vira três itens; um zip com dois shapefiles e um GeoTIFF vira três itens.
  • Cada item bem-sucedido vira uma fonte de dados. O nome é o nome da camada ou, se não houver, o nome do arquivo sem extensão. Você pode renomear depois em Configurações.
  • Dados vetoriais são convertidos para WGS84 (EPSG:4326), as geometrias inválidas são corrigidas e os nomes das colunas ficam em minúsculas, com apóstrofo, hífen e # trocados por _. Pontos, linhas e polígonos passam a ser do tipo "multi" (vários por feição) quando necessário.
  • Rasters são guardados como GeoTIFF otimizado para a nuvem (COG), sem perda de qualidade. Uma versão para exibição no mapa é gerada logo depois; até lá a fonte mostra visualização Gerando.
  • Para camadas vetoriais, o mapa fica pronto um pouco depois da fonte. A fonte já pode ser usada em projetos nesse intervalo.
  • O arquivo original conta no Armazenamento da organização.

Estados de um envio¶

Estado Significado
Na fila O arquivo chegou e espera processamento.
Processando Os itens estão sendo descobertos e convertidos.
Concluído O envio terminou. Pode haver itens que falharam: confira o cartão.
Falhou O arquivo não pôde ser aberto ou não continha nenhum dado reconhecido.

Um envio só falha inteiro quando nada pôde ser lido. Se ao menos um item foi encontrado, o envio termina como Concluído e cada item traz o próprio resultado: Concluído, Falhou (com a mensagem de erro) ou Ignorado.

Erros comuns¶

O que você vê Causa e o que fazer
Tipo de arquivo não suportado Extensão fora da lista. Compacte shapefiles, MapInfo e .gdb em um .zip.
Item Ignorado A camada não tem geometria (tabela sem coordenadas, CSV sem colunas lon/lat). Adicione as coordenadas e envie de novo.
"vector source must use an earth-referenced CRS" O arquivo não declara CRS ou usa um sistema local. Defina o CRS antes de enviar.
"no supported datasets found in upload" O zip não tinha nenhum arquivo reconhecido, ou o arquivo está corrompido.
"uploaded object checksum mismatch" O arquivo chegou diferente do que foi lido no seu computador. Envie de novo.
"processing stopped before this dataset finished" O item era grande demais para a memória do processamento. Divida a camada ou simplifique-a.
"could not start import" Falha temporária ao iniciar o processamento. Tente de novo mais tarde.

Um envio com erro não bloqueia o resto

Como cada item é independente, um shapefile com problema dentro do zip não impede que os outros virem fontes de dados. Corrija só o que falhou e envie esse arquivo em um novo envio.

Enviar pela linha de comando¶

O tn faz o mesmo envio a partir de um terminal, útil para scripts e para arquivos grandes. Detalhes de instalação e login em Linha de comando tn.

tn uploads create meu-catalogo ./dados.zip --wait
tn uploads list meu-catalogo
tn uploads get meu-catalogo <id-do-envio> --wait
tn uploads delete meu-catalogo <id-do-envio>
  • --wait consulta o estado a cada 2 segundos e desiste depois de 5 minutos; o processamento continua no servidor mesmo assim. Use tn uploads get para conferir depois.
  • tn uploads get mostra os itens do envio e as fontes de dados criadas.
  • Um envio só pode ser excluído enquanto está Na fila ou Falhou. Para remover dados que já viraram fontes, exclua as fontes de dados.
  • tn datasources list meu-catalogo lista as fontes do catálogo; use --json em qualquer comando para saída legível por máquina.
